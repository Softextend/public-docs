== POSTIS INTEGRATION

=== 1. Overview
Postis Integration connects Microsoft Dynamics 365 Business Central with the Postis shipping platform. When a sales order is shipped, a courier order is created in Business Central. From the courier order, the shipment is sent to Postis, which returns the AWB, the shipping label and the delivery status. The shipment data does not have to be entered again in the courier's platform.

An active Postis account and Postis API credentials are required.

=== 2. Setup
Set up the app in this order:

. *Courier Setup* - the general settings:
** No. Series - the number series for courier orders.
** Return Send Type - the send type for courier orders created from sales return orders.
** Cash Payment Method - the payment method that marks a sales order as cash on delivery. For these orders, the cash on delivery amount is filled in with the invoice value including VAT.
. *Courier Send Type* - the send types. FORWARD (deliveries) must exist, otherwise courier orders are not created automatically.
. *Couriers* - the carriers available through Postis.
. *Parcel Items* - predefined parcels (envelopes, packages, pallets) with weight and dimensions, to fill in the shipment parcels faster.
. *Courier User Setup* - one record for each Postis connection:
** ID - the code of the connection.
** Shipping Agent Code - the shipping agent that ships through Postis (e.g. POSTIS). Only sales orders with this shipping agent get a courier order automatically.
** Courier User ID and Courier User Password - the Postis API account. The password is stored encrypted in the isolated storage of the app, not in a database table. The page shows only *** when a password is set.
** Client ID and Sender Location Id - your client and pick-up location identifiers in Postis.
** API URIs - Authentication, Create Shipment, Get Estimated Cost, Trace Shipment, Delete Shipment and Get Label. Postis provides the values (e.g. https://shipments.postisgate.com/api/v1/clients/shipments).

=== 3. Courier orders from sales orders
When a sales order is posted as shipped and its shipping agent has a *Courier User Setup*, a courier order is created automatically, for every user who posts, with or without a Postis license. The courier order takes over:

* Recipient - the ship-to address of the sales order or, if there is none, the customer's address.
* Sender - the location of the sales order and the Sender Location Id of the Postis connection.
* References - the sales order no. (Client Order Id) and the posted sales shipment no. (Shipment Reference).
* Values - the invoice value including VAT and, for cash on delivery, the cash on delivery amount.
* Lines - the lines of the posted sales shipment.

Users with a license are then asked whether to open the courier order.

If the courier order cannot be created, the posting is kept and users who can create courier orders get a notification. The courier order can be created later with *Create Courier Order* on the posted sales shipment; a shipment never gets a second courier order. Exception: when posting from an inventory pick, or with a posting number series set to Date Order, an error in the courier order stops the posting.

=== 4. Courier orders from sales return orders
On a sales return order, *Create Courier Order* creates a courier order for picking up the returned goods. The customer becomes the sender, the location becomes the recipient, and the Return Send Type from *Courier Setup* is used.

=== 5. Working with a courier order
The *Courier Order* card shows the sender and the recipient, the *Shipment Parcels*, the *Courier Order Lines* and the *Trace Shipment* history. A courier order can be changed while its status is Not Sent or Deleted.

The actions on the card:

* Get Estimated Cost - asks Postis for the estimated shipping cost.
* Create Shipment - sends the order to Postis. Postis returns the AWB and the shipping cost, and the status becomes In Progress.
* Download AWB - downloads the shipping label.
* Trace Shipment - gets the delivery history. When Postis reports the final status, the status becomes Completed.
* Delete Shipment - cancels the shipment in Postis, clears the AWB and sets the status to Deleted. The order can then be changed and sent again.

On *Courier Order Lines*, *Get Sales Shipment Lines* and *Get Return Sales Lines* add lines from other documents.

Reports:

* *Update Trace Shipment* - updates the delivery history of all courier orders In Progress. Schedule it in the job queue.
* *Courier Statistics* - shipments and costs by courier, for a period.

=== 6. Licenses and permissions
Postis Integration is licensed per user, per month. Licenses are bought in Microsoft Marketplace and assigned to users in the Microsoft 365 admin center.

* Users with a license can use everything in this document, within the permission sets assigned to them in Business Central.
* Users without a license cannot open the Postis pages, reports or actions, and the Courier Order No. and AWB fields on purchase invoice lines are hidden for them. They can still post sales orders, and the courier order is created for them.
* Microsoft partners with delegated access (GDAP) can set up and support the app without a license. They cannot run job queue entries.

Permission sets, each one including the previous one:

* *Postis - Read* - shows courier orders, parcels, tracking and master data. No setup pages and no Postis credentials. Included in D365 READ and D365 TEAM MEMBER.
* *Postis - User* - creates and changes courier orders, sends them to Postis and tracks the shipments. Included in D365 BASIC and D365 BUS FULL ACCESS.
* *Postis - Full Access* - also the setup pages and master data, including the *Courier User Setup*. Included in SUPER. Assign it only to administrators.

Job queue entries run with the license and permissions of the user who sets them to Ready. Use a licensed user for the *Update Trace Shipment* job.
